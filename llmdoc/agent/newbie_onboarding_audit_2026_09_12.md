调查日期：2026-09-12。生产只读快照：18:29—18:49（Asia/Shanghai）。本地与生产代码均为 `3ebb7f59`，生产服务处于 active。调查包含实际代码审查、隔离模拟、生产 MySQL 聚合和近三天命令日志；未修改游戏逻辑或生产数据，未重启服务。

## 结论

大量1级角色已经尝试游戏并获得足够经验。当前最明确的功能故障是：**新手任务被每日任务清理逻辑跨日过期，随后无法恢复；历史新手任务还存在数据库状态字符串与查询条件不一致的问题。** 当天的最大任务断点在观察之后的导航教学，首次升级反馈又被任务顺序推迟。

升级本身无需长时间积累：一区1→2需10经验，二区需20，均100%成功；序章就会给足。玩家必须主动发送“突破”，经验不会自动转成等级。

这些证据能证明功能故障及玩家停留位置，无法量化每个故障分别造成多少真实流失，也不能把所有1级角色等同于完全没有玩过。

## 确定故障：跨日清理破坏新手任务

完整调用链：

1. 任意已注册玩家发送“任务统计/委托统计”。该命令没有30级门槛。
2. `daily_task/commands.py:364` 创建服务，`:392` 调用 `get_task_summary()`。
3. `daily_task/service.py:294` 的统计路径先调用 `check_and_cleanup_expired_tasks()`；生成、接取等路径也会调用。
4. `infrastructure/repositories/daily_task_repository.py:164` 查询日期早于今天且状态为 `available/accepted` 的记录，**没有排除 `is_tutorial`**，也未限定玩家或区服。
5. `daily_task/service.py:401` 将查出的任务逐条标为过期。
6. `quest/novice_quest_service.py:163` 只查 `status='accepted'`；之后观察、修炼等动作找不到任务，直接返回 `(False, None)`。
7. 初始化只在注册处触发；初始化本身也会因为存在旧任务而拒绝重建（`:80—97`）。

这是跨自然日问题。23:59新建的任务，00:01就可能被其他玩家触发的清理作废，无须满24小时。日期属于当前任务步骤，若当天推进出新步骤，该步骤能暂时保留到下次跨日清理。

清理日期缓存属于服务实例；每条命令重新构造服务，会在同一天重复扫描。但影响新手的关键错误是缺少教程排除条件。

隔离SQLite模拟加载实际任务模型、repository、service、novice service及 `safe_session`，只替换无关外围依赖。种入两区昨日教程、今日教程、历史异常状态教程和昨日普通任务，以另一位1级角色调用任务统计：

```text

昨日二区教程 -> expired
今日教程 -> accepted
历史教程 -> TaskStatus.ACCEPTED
昨日普通任务 -> expired

过期教程：current None / observe (False, None) / reinit False
历史教程：current None / observe (False, None) / reinit False
今日教程：current 存在
```

## 确定故障：历史状态数据无法被查询识别

生产存在 **2,075条 `status='TaskStatus.ACCEPTED'` 教程记录，涉及2,066名角色**。角色注册时间覆盖2025-12-03至2026-07-22。当前查询只接受小写字符串 `accepted`，这批记录不会被识别为当前任务。

Git证据：

- `7b0c6dfe`（2025-12-02）：向字符串列传枚举对象。
- `fbe8d19f`（2025-12-06）：查询改为 `.value`，新手任务写入仍传枚举对象。
- `e527018c`（2026-07-22）：两处写入改为 `.value`；对应迁移没有修复这批状态值。

无连接测试中，PyMySQL把枚举转为字符串 `'TaskStatus.ACCEPTED'`，与生产值一致。提交时间不等同于部署时间；生产现存记录直接证明至少这批历史数据仍未归一化。

恢复时需要考虑同一角色多条历史记录，仅恢复正确的未完成步骤并防止重复发奖。单纯修正新写入无法修复存量。

## 其他已核实的问题

1. **加点/突破依赖顺序错误。**第5步要求加点，第6步才教突破；初始属性点为0，第5步奖励的10点又需要先完成加点。属性不足提示只报剩余0，没有引导突破。
2. **提前达到等级不回填任务。**第6步要求当前事件为 `level_up` 且等级至少2。提前升到2级再进入该任务，查看面板不会补完成，还得再次成功突破（`novice_quest_service.py:378`）。
3. **连续突破缺少新手任务钩子。**普通突破有检测，连续突破没有，公共升级钩子也未补上（`cultivate/core.py:828`、`:946`，`social/level_hooks.py`）。
4. **满血用药阻断。**第8步要求使用回春散，满血时物品效果返回失败，任务检测不会执行（`item/item_effects.py:90`、`item/inventory.py:321`）。
5. **第9步入口等级不匹配。**任务说先查看委托、30级后接取，但“任务”命令整体在30级前拒绝，无法推进（`daily_task/commands.py:29`）。
6. **第9步和章末奖励物品ID不存在。**配置写 `sweep_order`，物品定义为 `sweep_token`，发奖时抛 `ValueError`。全库没有第10步及后续章节记录，与前述阻断吻合；缺少记录本身不能单独证明异常触发次数。
7. **第二章签到不回填。**当天已经签到，再进入签到任务后重复签到会提前返回，需等次日；该问题目前受到第一章阻断遮蔽。
8. **累计修炼进度不展示。**会保存1/3、2/3，但未完成时仅返回普通修炼结果。未找到独立的当前新手任务查询入口；“任务”实际通向每日委托。
9. **按钮文案与操作不一致。**`utils_markdown.py:95` 的命令按钮使用 `type=2`，不设置 `enter=True`。QQ协议默认只填入输入框，仍需玩家发送。实际adapter序列化已确认缺少enter；真实客户端尚未手工操作验证。蓝字指令使用另一协议，不直接套用此结论。参考：[QQ按钮协议](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/trans/msg-btn.html)。
10. **发送失败后的引导恢复不完整。**注册/首战奖励先提交，再发卡片。注册成功卡发送失败后重发注册只提示已有账号；首战奖励卡失败后重试只给简短完成提示。隔离模拟确认奖励不会丢失或重复发放，但未证实该异常在生产造成大量新人中断。

第4—7项主要影响后续上手，不能直接用于解释全部1级停留。
