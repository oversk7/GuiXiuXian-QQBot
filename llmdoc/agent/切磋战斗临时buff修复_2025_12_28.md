# 切磋战斗临时buff属性加成修复记录

## 修复概述

**问题**: 切磋战斗(PVP)中,临时buff(如暴怒丹临时增加攻击力)没有纳入战斗属性计算
**根本原因**: 调用`execute_player_turn()`时传递原始`player.attack`,而非已缓存的`player._cached_attack`
**修复日期**: 2025-12-28
**影响范围**: 切磋PVP战斗(已修复),副本PVE战斗(底层已正确使用缓存,无需修复)

---

## 问题分析

### 1. 问题表现
- 玩家使用暴怒丹等临时buff后,切磋战斗伤害未增加
- `【面板】`显示属性已包含临时buff
- 临时buff过期后切磋战斗正常

### 2. 代码流程分析

**属性缓存流程** (已正确实现):
```python
# plugins/xiuxian_game/battle/integration_helper.py:1166-1172
player1_base_attrs = await player1.get_effective_attributes(session)
player1_battle_attrs = await BattleAttributeCalculator.calculate_effective_attributes_async(player1, session)
player1._cached_attack = player1_base_attrs.get('attack', player1.attack)
```

**战斗调用流程** (问题所在):
```python
# plugins/xiuxian_game/battle/integration_helper.py:1257-1258 (错误示例)
attack_result = engine.execute_player_turn(
    player1, player2, player1.attack, is_skill=False  # ❌ 应使用 player1._cached_attack
)
```

### 3. 根本原因
- 系统已正确获取并缓存包含临时buff的属性到`_cached_attack`等字段
- 但调用`execute_player_turn()`时传递的是`player.attack`原始值
- 导致临时buff加成在战斗计算中被忽略

---

## 修复方案

### 修改文件
`plugins/xiuxian_game/battle/integration_helper.py`

### 修改位置
将所有`execute_player_turn()`调用的第三个参数从`player.attack`改为`player._cached_attack`

#### 修改清单 (共6处)

| 行号 | 修改前 | 修改后 |
|------|--------|--------|
| 208-209 | `first_player.attack` | `first_player._cached_attack` |
| 283-284 | `second_player.attack` | `second_player._cached_attack` |
| 1257-1258 | `player1.attack` | `player1._cached_attack` |
| 1321-1322 | `player2.attack` | `player2._cached_attack` |
| 1413-1414 | `player2.attack` | `player2._cached_attack` |
| 1467-1468 | `player1.attack` | `player1._cached_attack` |

### 代码对比

**修改前**:
```python
attack_result = engine.execute_player_turn(
    player1, player2, player1.attack, is_skill=False  # ❌ 原始值
)
```

**修改后**:
```python
attack_result = engine.execute_player_turn(
    player1, player2, player1._cached_attack, is_skill=False  # ✅ 包含临时buff
)
```

## 技术细节

### 属性缓存机制
```python
# 基础属性缓存 (integration_helper.py:1176-1190)
player1._cached_attack = player1_base_attrs.get('attack', player1.attack)
player1._cached_defense = player1_base_attrs.get('defense', player1.defense)
player1._cached_max_hp = player1_base_attrs.get('max_hp', player1.max_hp)
player1._cached_max_mp = player1_base_attrs.get('max_mp', ...)
player1._cached_agility = player1_base_attrs.get('agility', player1.agility)

# 战斗属性缓存 (integration_helper.py:1193-1194)
player1._cached_battle_attrs = player1_battle_attrs
```

### 为什么不修改engine内部?
- `execute_player_turn()`接收attack值作为参数
- 若修改engine为自动查询`_cached_attack`,需要修改战斗引擎核心
- 当前方案最小化修改范围,降低风险
- 保持engine接口不变,仅调整调用层传参

## 备注

本次修复是典型的"缓存-使用不一致"问题:
- 上游已正确计算并缓存包含buff的属性
- 下游使用时却读取原始字段值
- 解决方案是统一使用缓存字段

此类问题的预防措施:
- 统一属性访问接口
- 减少直接访问player字段
- 增加单元测试覆盖属性计算
