## Report (The Answers)

### 1. 移动系统现状

#### 1.1 现实世界移动

**机制**:
- 命令: 【导航 x y】启动自动导航或查看进度
- 坐标范围: -500 ≤ x,y ≤ 500（对称范围）
- 成本: 无即时成本，仅消耗时间
- 冷却: 无冷却机制，可随时更新导航目标
- 速度计算: `speed = agility / 2500` 格/秒（基于敏捷属性）

**反馈信息**:
- 启动导航: 显示目标坐标、当前坐标、速度、预计耗时
- 查看进度: 实时显示现实坐标(含浮点精度)、诡域位置(若在诡域)、剩余时间
- 中断导航: 显示停留坐标

**设计特点**:
- 导航数据持久化（重启不丢失）
- 在诡域中可继续导航（作用于现实世界坐标）
- 返回时自动推进导航进度至"返回位置"

#### 1.2 诡域内移动

**机制**:
- 命令: 上/下/左/右（单个汉字，正则匹配）
- 坐标范围: -5 ≤ x,y ≤ 5（10x10网格，中心在0,0）
- 成本: 1点理智值(MP)，可通过诡域配置调整(mp_cost)
- 冷却: 无冷却，但理智耗尽后角色死亡(hp=0)
- 速度: 即时移动

**反馈信息**:
- 移动成功: 显示新坐标、当前格子事件描述(怪物/材料/宝箱等)
- 月卡自动采集: 若有权限自动收集材料或宝箱
- 移动失败: 显示边界提示或理智不足

**格子事件系统**:
- MATERIAL: 材料采集（个人事件，记录looted_by字段）
- TREASURE: 宝箱探索（全局事件）
- EMPTY/ELITE: 诡异战斗
- REST: 驿站休息
- MERCHANT: 商人商店

### 2. 坐标系统设计

#### 2.1 双层坐标体系

```
Player模型坐标字段:
├─ 现实世界 (region="大都会")
│  ├─ real_world_x: -500 ~ 500
│  ├─ real_world_y: -500 ~ 500
│  ├─ x,y: 兼容性字段(同步于real_world_*)
│  └─ region: "大都会"
│
└─ 诡域 (dungeon_level > 0)
   ├─ dungeon_level: 1~无限
   ├─ dungeon_x: -5 ~ 5
   ├─ dungeon_y: -5 ~ 5
   ├─ x,y: 兼容性字段(同步于dungeon_*)
   └─ region: "Nlevel层诡域"
```

**逻辑**:
- get_current_coordinates(): 根据dungeon_level返回活跃坐标
- enter_dungeon(level): 保存现实世界坐标，初始化诡域坐标为(0,0)
- exit_dungeon(): 恢复现实世界坐标，清除诡域信息
- move_in_current_world(dx, dy): 智能选择更新哪组坐标

#### 2.2 区域概念

**已实现**:
- 现实世界: region="大都会" (统一区域，坐标-500~500)
- 诡域: region="N层诡域" (无限层级，每层独立坐标系-5~5)
- 旧系统: 命名诡域(兼容，如"秘密森林"等)

**缺失**:
- 无表世界的地理分区(如"华夏大陆"、"异域沙漠"等)
- 无区域事件(如特定区域才能进行的任务)

#### 2.3 格子与地点系统

**WorldTile** (世界格子表):
- 存储region, x, y唯一确定的格子
- event_type: MATERIAL/TREASURE/EMPTY/ELITE/REST/MERCHANT
- state: JSON存储事件状态(怪物属性/物品/NPC访问记录等)
- seed: 确定性生成种子(按天刷新)

**Location** (地点表):
- 存储固定地点(市集、打工地、工坊等)
- functions: JSON存储该地点的功能(market/part_time_job/forge等)
- NPCs: 关系表存储驻守NPC

**问题**: Location和WorldTile是两个独立系统，逻辑不完全统一

### 5. 用户体验问题

#### 5.1 新手寻找第一个功能的流程

**现状问题**:
1. 新手没有导航目标提示
2. 【帮助】或【指南】应该告诉新手地点坐标
3. 需要手动运行: 导航 x y → 到达地点 → 【观察】查看地点信息

**改进需求**:
- 新手任务应提示目标坐标
- 首次导航应有引导

#### 5.2 寻找目标的无聊度

**现状**:
- 现实世界导航是等待过程(纯时间消耗，无互动)
- 诡域移动有格子事件(随机遭遇，相对有趣)
- 导航过程中无随机事件(与移动比较单调)

**可能改进**:
- 导航过程中有概率触发"路遇"事件(商人/怪物/NPC)
- 导航中可被其他玩家"抢劫"或"交互"

#### 5.3 社交发现

**现状**:
- 【观察】显示当前坐标同位置的玩家(max_distance=0)
- 【观察】显示3格内的玩家(用于显示"附近有人"提示)
- 无全局在线玩家列表(因此无法主动寻找玩家)

**问题**:
- 玩家难以聚集在特定地点(无玩家位置地图)
- 社交活动受位置限制但无发现机制

**优化空间**:
- 诡域10x10共100个格子，每天刷新

## Conclusions (关键发现)

1. **移动系统现状**: 实现了诡域单格移动(上下左右)和现实世界自动导航(导航x y)，但两个系统独立，体验不统一。

2. **坐标体系完善**: 双层坐标系(现实-500~500, 诡域-5~5)设计合理，代码实现也正确。

3. **导航功能不完整**: 支持自由坐标导航，但无法导航到"地点"(市集/工坊)，需要手动查表找坐标。

4. **位置系统两套**: Location(地点表)和WorldTile(格子表)是两个独立系统，导致地点信息重复且不好查询。

5. **NPC位置隐隐**: NPC存在于Location，但无玩家可用的位置查询命令，玩家无法主动寻找NPC。

6. **位置权限虚设**: 市集、工坊、打工等可全局访问，无需到达对应地点，削弱了位置系统的游戏意义。

7. **导航体验单调**: 现实世界导航只有时间推进，无中途事件；诡域有格子事件(怪物/物品)相对有趣。

8. **社交发现困难**: 无在线玩家位置地图，难以形成玩家聚集(除非刻意约定坐标)。

9. **性能未优化**: 坐标范围查询可能N+1或全表扫描，缺少地理索引。

10. **改进优先级**: 一键前往地点 > NPC位置查询 > 任务位置系统 > 位置权限强制。

## Relations (代码关系)

**导航系统架构**:
```
用户命令(导航/中断导航)
    ↓
navigation.py (_update_nav_position)
    ├─ 读取 Player.real_world_x/y
    ├─ 计算 NavigationTask.target_x/y
    ├─ 基于 agility 计算速度
    └─ 写回 Player.real_world_x/y

现实世界移动(自动导航):
    ├─ 启动: 【导航 x y】
    ├─ 存储: NavigationTask表
    ├─ 推进: 每次命令调用_update_nav_position()
    └─ 完成: 到达目标删除任务

诡域移动:
    └─ 命令(上下左右) → move_in_current_world() → WorldTile事件查询
```

**位置与导航的缺失连接**:
```
Location(地点表)  ←无直接关联→  NavigationTask(导航表)
    ↓                                    ↓
- 市集坐标                     - 目标坐标(自由输入)
- 工坊坐标                     - 支持任意x,y
- NPC驻守地点

问题: 玩家无法用【导航 市集】这样的语法
```

**NPC位置系统的断链**:
```
Location.npcs → [NPC对象]
    ↓
NPC.name, NPC.location

但玩家命令层无"查找NPC"命令
    ↓
玩家只能: 【观察】→看当前地点NPC → 无法主动搜索
```

**任务系统与位置的缺失**:
```
Quest模型: 无target_location或target_coords字段
    ↓
任务页面: 无"前往XXX地点"提示
    ↓
玩家体验: 完成任务需要自己猜位置
```
