# 诡修仙系统重设计方案 - 新手体验破局

**设计日期**: 2025-12-02
**设计者**: game-designer 代理
**基于数据**: 1,736 玩家样本 + 代码架构分析
**文档类型**: 系统设计方案

---

## 1. 执行概要

### 核心问题

诡修仙当前面临的最大危机不是数值膨胀或经济通胀，而是**新手玩家根本不知道该干什么**。77%的玩家卡在0-10级，不是因为游戏难度高，而是因为:

1. **认知负荷过载**: 15+子系统同时开放，没有渐进式解锁
2. **目标缺失**: 没有明确的"下一步该做什么"的引导
3. **信息洪流**: QQ群文字刷屏，关键信息淹没在大量输出中
4. **成就感缺失**: 早期数值成长过慢，玩家感受不到进步

### 破局策略

不是修数值，而是**重构认知路径**:
- 从"大而全的沙盒"转向"有序展开的成长线"
- 从"功能堆砌"转向"渐进式功能解锁"
- 从"文字洪流"转向"关键信息突出"

### 2.2 资源流动分析 (Sources & Sinks)

#### 资源来源 (Sources)

| 来源类型 | 获取方式 | 效率评级 | 新手可达性 |
|---------|---------|---------|----------|
| **修炼** | 每5分钟 | 基准 1x | ✅ 立即可用 |
| **闭关** | 被动挂机 | 中等 2-5x | ⚠️ 需理解机制 |
| **诡域探索** | 消耗MP格子 | 中高 5-10x | ❌ 需导航+理解坐标 |
| **扫荡令** | 消耗道具 | 极高 75-300x | ❌ 需购买(10万金币) |
| **药品刷副本** | 无限续航 | 高 8.25x | ⚠️ 漏洞(已识别) |
| **打工** | 每日限制 | 低 | ✅ 立即可用 |
| **邀请奖励** | 社交传播 | 一次性 | ✅ 立即可用 |

**问题诊断**:
- **效率断层**: 基础修炼(1x) → 扫荡令(300x)，中间缺少平滑过渡
- **新手困境**: 高效率资源来源都需要前置知识或金币，新手只能用最低效的修炼
- **漏洞利用**: 药品刷副本成为中期玩家主要升级手段，正常玩法被架空

#### 资源消耗 (Sinks)

| 消耗类型 | 消耗场景 | 消耗量级 | 匹配度 |
|---------|---------|---------|-------|
| **突破失败** | 30级后概率失败 | 损失30%经验 | ⚠️ 挫败感强 |
| **装备修理** | 战斗耐久度消耗 | 中等金币 | ✅ 合理 |
| **装备升阶** | 主动升级 | 材料+金币 | ❌ 材料获取困难 |
| **商店购买** | 药品/道具 | 低(100金币/药) | ❌ 价格过低 |
| **跑商成本** | 市场差价 | 变动 | ✅ 合理 |
| **公会建筑** | 集体投资 | 高 | ⚠️ 需加入公会 |

**问题诊断**:
- **Sink不足**: 新手阶段几乎没有消耗，导致资源积累但无用处
- **Sink过猛**: 突破失败直接损失30%经验，新手不敢尝试
- **价格错配**: 药品价格(100金币)远低于其价值(可无限续航副本)

**耦合度分析**:
- **核心瓶颈**: 等级系统是所有功能的前置，但升级路径不清晰

- **新手陷阱**: 任何一个环节的卡顿都会导致整个循环停滞

## 3. 平台/UX审查 (QQ Bot Specifics)

### 3.1 QQ群文字交互的本质约束

| 约束类型 | 具体表现 | 对设计的影响 |
|---------|---------|-------------|
| **Request-Response** | 每次指令需等待回复 | 不能设计需要高频交互的玩法 |
| **群聊刷屏** | 多人同时游戏时消息混杂 | 必须简化输出，突出关键信息 |
| **无状态保持** | 每次指令独立 | 不能设计需要"上下文记忆"的交互 |
| **文字阅读疲劳** | 超过3行难以快速解析 | 必须使用视觉分隔符和emoji |
| **移动端阅读** | 手机屏幕小 | 宽度限制在40字符内 |

### 3.2 当前UX问题诊断

#### 问题1: 命令复杂度过高

**表现**:
```
修炼 (简单) ✅
突破 (简单) ✅
加点 力 10 (中等) ⚠️
装备升阶 装备ID (中等) ⚠️
镶嵌宝石 装备ID 宝石ID 槽位 (复杂) ❌
投资气运 <代码> <数量> [银行] (复杂) ❌
```

**数据支撑**:
- 77%玩家卡在Lv.0-10，说明连基础指令都没掌握
- 帮助文档长达1000+行，新手无法快速找到需要的指令

**根本原因**:
- 没有分级展示：新手看到的指令列表和老玩家一样
- 缺少"快速开始"：没有"前3步应该做什么"的明确引导

#### 问题2: 信息密度过载

**当前修炼输出示例**:
```
你在黑焰里看见自己的影子喘息。
━━━━━━━━━━━━━
修炼结果:
• 获得经验: 127 (基础50 + 月卡20% + 公会15% + 阴宅10%)
• 当前经验: 1,234 / 10,000
• 距离升级: 8,766
• 公会加成: 15% (来自灵堂Lv.3)
• 阴宅加成: 10% (使用张三的阴宅, 已扣除100金币)
━━━━━━━━━━━━━
⏰ 冷却时间: 5分钟
```

**问题**:
- 信息行数过多(9行)，在群聊中容易被刷掉
- 加成来源详细，但新手不关心(甚至不理解"公会灵堂"是什么)
- 关键信息(获得经验、距离升级)淹没在细节中

**优化后示例** (新手版):
```
🔥 修炼完成 +127经验
📊 Lv.5 [████░░░░] 1,234/10,000
⏰ 5分钟后可再次修炼
💡 还需修炼 69次可升级
```

#### 问题3: 缺少渐进式引导

**当前新手流程**:
```
注册 → 查看面板 → ??? (玩家不知道下一步)
```

**问题**:
- 注册后没有"新手任务链"
- 没有"成就系统"提示玩家下一个目标
- 面板显示大量未解锁功能，但不告诉玩家如何解锁

### 3.3 文字密度分析

| 功能 | 当前输出行数 | 适宜行数 | 优化方向 |
|-----|------------|---------|---------|
| 修炼结果 | 9行 | 3-5行 | 隐藏加成来源，仅显示总值 |
| 战斗日志 | 15-30行 | 5-8行 | 折叠回合细节，仅显示关键转折 |
| 背包查看 | 10-50行 | 10行 | 分页显示，默认只显示装备/消耗品 |
| 公会面板 | 20行 | 8行 | 分离"公会概览"和"公会详情" |
| 装备属性 | 12行 | 6行 | 隐藏未激活的镶嵌槽 |

## 4. 数据证据分析

### 4.1 新手留存危机的数量化证据

**基于1,736玩家样本**:

| 等级范围 | 玩家数 | 占比 | 诊断 |
|---------|-------|------|------|
| 0-10级 | 1,335 | 77% | 🔴 严重卡关 |
| 11-20级 | 197 | 11% | 🟠 成长断层 |
| 21-30级 | 103 | 6% | 🟡 精英玩家 |
| 31+级 | 101 | 6% | 🟢 核心玩家 |

**关键发现**:
- **断崖式流失**: 0-10级占77%，11-20级骤降至11%，流失率高达**86%**
- **成长阻力**: 从11级开始玩家数量稳定下降，说明每个阶段都有流失

### 4.2 经济失衡的数量化证据

**金币分布** (推测基于已知最高值34.4亿):

```
最高金币: 3,440,000,000 (34.4亿)
预估中位数: 5,000 (新手玩家拉低平均值)
预估基尼系数: 0.85-0.90 (极度不平等)
```

**药品价格失衡**:
```
回春散售价: 100金币
恢复效果: 40 HP
副本格子消耗: 1 MP/格
凝神草售价: 100金币
恢复效果: 40 MP (可探索40格)

经验计算:
- 40格诡域 ≈ 2,000经验
- 成本: 100金币
- 效率: 20经验/金币

对比正常修炼:
- 5分钟 ≈ 50经验
- 1小时 ≈ 600经验
- 药品刷副本 1小时 ≈ 5,000经验 (8.3倍)
```

### 4.3 系统复杂度的数量化证据

**基于代码库分析**:

| 维度 | 数量 | 新手需掌握 | 比例 |
|-----|------|-----------|------|
| 指令总数 | 150+ | ~20 | 13% |
| 子系统数 | 15 | ~3 | 20% |
| 数据模型字段(Player) | 87 | ~15 | 17% |
| 物品种类 | 200+ | ~10 | 5% |
| 装备效果类型 | 45+ | ~5 | 11% |

**认知负荷计算**:
- 新手需要理解的核心概念: **50+**
- 实际文档提供的概念: **200+**
- 信噪比: **1:4** (75%的信息对新手无用)

### 4.4 成长曲线的数学分析

**升级经验需求** (基于`config.yaml`):
```python
# 1-10级 (早期倍率=10)
exp(level) = 10 * level * 10 = 100 * level
Lv.1→2: 100经验
Lv.10→11: 1,000经验

# 11+级 (晚期倍率=6)
exp(level) = 10 * level * 6 = 60 * level
Lv.11→12: 660经验
Lv.20→21: 1,200经验
```

**新手修炼效率**:
```
基础修炼: 50经验/次 (5分钟冷却)
每小时: 12次 × 50 = 600经验/小时

Lv.1→10 所需经验: 100+200+...+1000 = 5,500经验
所需时间: 5,500 / 600 ≈ 9.2 小时 (纯修炼时间)

实际问题:
- 新手不会每5分钟准时修炼
- 不知道闭关、副本等高效方式
- 实际升到Lv.10可能需要 20-30 小时游戏时间
```

**对比老玩家**:
```
扫荡令: 150,000经验/次
Lv.1→10仅需: 5,500 / 150,000 = 0.037次 = 瞬间

药品刷副本: 5,000经验/小时
Lv.1→10仅需: 5,500 / 5,000 ≈ 1.1小时
```

**结论**: 新手和老玩家的升级速度差距高达**1000倍**

## 5. 破局方案设计

### 5.1 新手引导重构 (P0 最高优先级)

#### 方案: 3阶段渐进式功能解锁

**设计哲学**: 不是限制功能，而是**引导注意力**

##### 阶段1: 新手村 (Lv.0-10) - "学会基础循环"

**解锁功能** (仅显示以下指令):
```
核心循环:
- 修炼 (获得经验)
- 突破 (提升等级)
- 加点 (分配属性)

辅助功能:
- 面板 (查看状态)
- 背包 (查看物品)
- 帮助 (查看指令)
```

**目标引导系统** (新增):
```
注册后自动触发:
━━━━━━━━━━━━━
🎮 新手引导 [1/5]
━━━━━━━━━━━━━
欢迎来到诡修仙!
你的第一个任务:

📌 使用【修炼】指令获得经验

完成后输入【下一步】继续
━━━━━━━━━━━━━
```

**新手任务链**:
1. 首次修炼 → 奖励: 500经验
2. 加点分配 → 奖励: 10属性点
3. 修炼3次 → 奖励: 1000经验 (直接升到Lv.2)
4. 首次突破 → 奖励: 回春散x10
5. 探索诡域 → 奖励: 扫荡令x1 (体验高效玩法)

**预期效果**:
- 新手在30分钟内完成Lv.0→5的成长
- 通过奖励加速，减少"无聊期"
- 建立"修炼→突破→加点"的核心循环认知

##### 阶段2: 成长期 (Lv.11-30) - "探索多样玩法"

**新增解锁**:
```
探索系统:
- 诡域探索
- 前往 (移动)
- 攻击 (战斗)

经济系统:
- 购买/出售
- 市集
- 银行

装备系统:
- 装备/卸下
- 装备升阶
```

**引导方式**: 每解锁一个等级档位(15级、20级、25级)推送提示
```
━━━━━━━━━━━━━
🎉 Lv.15 已解锁新功能!
━━━━━━━━━━━━━
🗺️ 诡域探索系统
现在可以使用【诡域探索】进入副本
获得经验速度是修炼的10倍!

💡 输入【诡域探索帮助】查看详情
━━━━━━━━━━━━━
```

##### 阶段3: 自由期 (Lv.31+) - "开放全部功能"

**解锁全部系统**:
- 公会、师徒、婚姻
- 炼丹、钓鱼、打工
- 气运投资、股票
- 世界Boss、周常活动

**设计要点**:
- 此时玩家已建立核心认知
- 通过公告推送新功能，而非一次性展示

```python
# 新增: 物品冷却管理器
class ItemCooldownManager:
    _cooldowns: dict[str, datetime] = {}  # {player_id: last_use_time}

    @classmethod
    async def check_cooldown(cls, player_id: str, item_id: str) -> tuple[bool, int]:
        """检查冷却时间
        Returns: (是否可用, 剩余秒数)
        """
        key = f"{player_id}:{item_id}"
        last_use = cls._cooldowns.get(key)

        if last_use is None:
            return True, 0

        elapsed = (datetime.now() - last_use).seconds
        cooldown = 10  # 10秒冷却

        if elapsed >= cooldown:
            return True, 0
        else:
            return False, cooldown - elapsed

    @classmethod
    def set_cooldown(cls, player_id: str, item_id: str):
        key = f"{player_id}:{item_id}"
        cls._cooldowns[key] = datetime.now()

# 修改: 恢复类物品效果
class RestoreHPEffect(IEffect):
    async def apply(self, player: Player, session, params: dict) -> str:
        # 检查冷却
        can_use, remaining = await ItemCooldownManager.check_cooldown(
            player.id, "heal_potion"
        )
        if not can_use:
            return f"⏰ 物品冷却中，剩余{remaining}秒"

        # 恢复HP
        value = params.get("value", 40)
        player.hp = min(player.hp + value, player.max_hp)

        # 设置冷却
        ItemCooldownManager.set_cooldown(player.id, "heal_potion")

        return f"恢复{value} HP (冷却10秒)"
```

```python
    percent = current / maximum
```

## 9. 设计哲学总结

### 9.1 从"功能驱动"到"体验驱动"

**过去的思维**:
```
我们有15个系统 → 全部展示给玩家 → 期望玩家自己探索
```

**新的思维**:
```
玩家需要明确目标 → 设计成长路径 → 渐进式解锁功能
```

### 9.2 QQ群游戏的本质

QQ群不是游戏客户端，是**社交平台**。玩家来QQ群的主要目的是**聊天**，游戏是**副产品**。因此:

1. **不能刷屏**: 每条指令输出≤5行
2. **不能高频**: 5分钟一次修炼是极限
3. **不能复杂**: 指令格式必须简单易记
4. **要有社交**: 公会、师徒、世界Boss是核心玩法

### 9.3 修仙游戏的核心乐趣

不是"数值膨胀"，而是:
- **成长感**: 从弱小到强大的过程
- **探索感**: 未知区域、隐藏BOSS、稀有材料
- **社交感**: 公会合作、师徒传承、结婚系统
- **收集感**: 装备图鉴、丹药配方、材料收集

当前问题: **新手连成长感都体会不到，就已经流失了**
