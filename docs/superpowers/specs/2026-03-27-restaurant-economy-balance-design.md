# 餐厅经济平衡重设计 - 客流分层与数据透明

> **状态**: 设计完成，待实现
> **创建日期**: 2026-03-27
> **设计者**: 头脑风暴 (Claude Code + 用户)

---

## 1. 问题陈述

当前餐厅系统存在三个核心问题：

1. **低级菜谱被完全淘汰** — 高级菜在利润率、绝对利润、品质倍率上全面碾压低级菜，无任何trade-off
2. **数据不透明** — 玩家看不到利润率、客流组成、产能利用率等关键经营数据，无法做策略决策
3. **缺乏策略深度** — 最优策略永远是"全上最贵的菜"，菜单配置没有意义

## 2. 设计目标

- 让不同等级菜谱都有存在价值，低级菜"薄利多销"，高级菜"高利润但客源有限"
- 让玩家能看到关键经营数据，做出有依据的策略决策
- 菜单搭配成为核心策略，混搭优于极端

## 3. 设计决策记录

| 决策项 | 选择 | 理由 |
|--------|------|------|
| 低级菜优势机制 | 客流结构驱动 | 最自然，不需要硬编码速度加成，策略深度最好 |
| 客人分层数 | 3层 | 简洁清晰，策略选择明确 |
| 数据透明度 | 实用策略向 | 显示决策所需数据，信息密度高但不冗余 |
| 改动范围 | 全面改造 | 可新增命令、优化显示，大幅提升体验 |

## 4. 客流分层系统

### 4.1 客人类型定义

| 客人类型 | 标识 | 接受的菜谱等级 | 声望满意 | 声望不满 |
|---------|------|-------------|---------|---------|
| 普通食客 | COMMON | 白/绿 | +1/人 | -3/人 |
| 富商 | WEALTHY | 绿/蓝/紫 | +3/人 | -5/人 |
| 贵宾 | VIP | 紫/橙 | +8/人 | -2/人 |

说明：
- 普通食客不满惩罚较高(-3)：占比最大，大量不满会快速拉低声望
- 贵宾不满惩罚较低(-2)：贵宾"吃不到就走了"，不会大闹，但满意奖励很高(+8)
- 富商不满惩罚最高(-5)：富商期望高，失望后会给差评

### 4.2 声望对客流结构的影响

随声望增长，高消费客人比例逐步提升，但普通食客永远是最大群体：

```python
REPUTATION_CUSTOMER_RATIO = [
    (0,     {"common": 0.65, "wealthy": 0.28, "vip": 0.07}),
    (1000,  {"common": 0.60, "wealthy": 0.30, "vip": 0.10}),
    (3000,  {"common": 0.52, "wealthy": 0.35, "vip": 0.13}),
    (5000,  {"common": 0.45, "wealthy": 0.38, "vip": 0.17}),
    (8000,  {"common": 0.40, "wealthy": 0.40, "vip": 0.20}),
]
```

查表逻辑：取不超过当前声望的最大阈值对应的比例。

### 4.3 客人与菜品的匹配映射

```python
CUSTOMER_TIER_RECIPE_MAP = {
    "common":  ["white", "green"],
    "wealthy": ["green", "blue", "purple"],
    "vip":     ["purple", "orange"]
}
```

注意绿色菜被普通食客和富商共同接受，是衔接两个群体的"万金油"等级。

### 4.4 结算流程改动

原流程：
```
所有客人 → 从所有菜品中随机消费
```

新流程：
```
1. 计算总客流（公式不变）
2. 按声望查表拆分为3组：common_count, wealthy_count, vip_count
3. 厨师做出的菜品按 recipe.tier 分类到3个桶
4. 每组客人按顺序消费匹配桶中的菜品
5. 未被消费的菜品 = 浪费（不产生收入，不影响声望）
6. 未被满足的客人 = 声望惩罚（按上表计算）
7. 日志记录各组的满足率
```

详细匹配逻辑：
```
for 每组客人类型 (common/wealthy/vip):
    可用菜品 = 所有tier在CUSTOMER_TIER_RECIPE_MAP[类型]中的已做菜品
    served = min(该组客人数, 可用菜品数)
    从可用菜品中取前served道计算收入
    unserved = 该组客人数 - served
    声望惩罚 += unserved × 对应惩罚值
    声望奖励 += served × 对应奖励值
```

## 6. 声望计算改动

### 6.1 新的声望变化公式

替换原有的统一声望计算，改为按客人类型分别计算：

```python
reputation_change = 0

# 按客人类型计算
for tier in ["common", "wealthy", "vip"]:
    served = tier_served[tier]       # 该类型被满足的客人数
    unserved = tier_unserved[tier]   # 该类型未被满足的客人数

    # 满意奖励
    reputation_change += served * SATISFACTION_BONUS[tier]

    # 不满惩罚
    reputation_change -= unserved * DISSATISFACTION_PENALTY[tier]

# 完美菜肴额外奖励（保留）
reputation_change += perfect_dish_count * 5

# 黑暗料理惩罚（保留）
reputation_change -= dark_dish_count * 2
```

### 6.2 声望奖惩配置

```python
SATISFACTION_BONUS = {
    "common": 1,
    "wealthy": 3,
    "vip": 8
}

DISSATISFACTION_PENALTY = {
    "common": 3,
    "wealthy": 5,
    "vip": 2
}
```

## 8. 策略模拟验证

### 场景：餐厅等级5，声望2000，30席，3个蓝色厨师（速度4道/时）

**场景1：纯白色菜单**
- 客流：~20人（普通12 / 富商6 / 贵宾2）
- 产能：12道白色菜
- 普通食客：12人全满足，收入 12×120 = 1,440金
- 富商：6人无菜可吃 → 不满 -30声望
- 贵宾：2人无菜可吃 → 不满 -4声望
- 声望：+12 -30 -4 = **-22**
- 净利润 ≈ 1,440 - 360(工资) - 696(食材) ≈ **384金/时**
- 结论：便宜但声望持续下降，不可持续

**场景2：纯紫色菜单**
- 产能：12道紫色菜
- 富商：6人可吃紫色，收入 6×4,200 = 25,200金
- 贵宾：2人可吃紫色，收入 2×4,200 = 8,400金
- 普通食客：12人无菜可吃 → 不满 -36声望
- 声望：+6×3 +2×8 -12×3 = 18+16-36 = **-2**
- 净利润 ≈ 33,600 - 360 - 14,480 ≈ **18,760金/时**
- 结论：短期利润高，但声望缓慢下降，长期不健康

**场景3：混搭菜单（白4 + 绿4 + 蓝4）**
- 普通食客12人 → 消费白+绿共8道（满足8人，4人不满）
- 富商6人 → 消费绿(剩余)+蓝共4道（满足4人，2人不满）
- 贵宾2人 → 无紫/橙菜（2人不满）
- 收入：白4×120 + 绿4×500 + 蓝4×900 = 480+2000+3600 = **6,080金**
- 声望：+8×1 +4×3 -4×3 -2×5 -2×2 = 8+12-12-10-4 = **-6**

**场景4：优化混搭（白5 + 绿5 + 蓝2）**
- 普通食客12人 → 白5+绿5=10道（满足10人，2人不满）
- 富商6人 → 蓝2（满足2人，4人不满）
- 贵宾2人 → 无菜（2人不满）
- 收入：5×120 + 5×500 + 2×900 = 600+2500+1800 = **4,900金**
- 声望：+10×1 +2×3 -2×3 -4×5 -2×2 = 10+6-6-20-4 = **-14**

**场景5：最优混搭（白3 + 绿4 + 蓝3 + 紫2）**
- 需厨房Lv4解锁紫色
- 普通食客12人 → 白3+绿4=7道（满足7人，5人不满）
- 富商6人 → 蓝3+紫部分=3+2=5道（但紫也被贵宾抢，这里先供富商）...
- 实际上产能只有12道，分配方式影响很大

通过模拟可见：**产能(12道)无法同时满足所有20人客流，核心策略是如何分配有限产能最大化收入+声望**。这正是我们想要的策略深度。
