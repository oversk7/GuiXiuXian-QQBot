# 装备词缀与铭文系统设计

## 1. 概述

### 1.1 背景

当前装备体系存在以下问题：

- **同名装备完全相同** — 每把"菜刀"属性一模一样，没有个体差异
- **锻造无惊喜** — 配方到成品完全确定，缺乏随机性和追求感
- **成长路径单一** — 只有升阶(+0到+10)一条线性路径
- **装备获取途径单一** — 只能通过锻造获得，怪物不掉落装备
- **战斗属性获取稀缺** — 暴击、穿透、闪避等战斗属性只有极少数宝石和装备效果能提供
- **装备效果绑死在装备上** — 镇魂幡的恐惧效果等无法自由搭配

### 1.2 设计目标

1. 引入DNF风格的随机词缀系统，让每件装备都有个体差异
2. 将装备效果剥离为独立的铭文物品，支持自由搭配build
3. 新增怪物掉落装备途径，丰富装备获取方式
4. 新增洗炼/分解系统，提供词缀优化手段
5. 全面兼容现有升阶/宝石/VIP装备体系
6. 词缀走战斗属性赛道，避免与现有百分比基础属性加成冲突

### 1.3 设计原则

- **存量无损** — 玩家已持有的老装备不受影响，视为"素装"（无词缀）
- **升阶兼容** — 升阶只影响基础属性（每阶+20%），词缀独立于升阶
- **VIP豁免** — VIP定制装备保留原有 special_effects，不参与词缀/铭文改造
- **战斗属性赛道** — 词缀和铭文提供战斗属性（暴击率、穿透等）和触发效果，不提供基础属性（攻防生敏），避免高等级百分比加成下固定值词缀无意义
- **渐进体验** — 低级装备词缀少，高级装备词缀多，给玩家持续追求目标

## 2. 系统架构

### 2.1 模块总览

| 模块 | 内容 | 与现有系统关系 |
|------|------|--------------|
| 装备词缀 | 锻造/掉落装备自带随机战斗属性词缀 | 新增，不影响升阶 |
| 铭文系统 | 独立效果物品，插入宝石孔（共用） | 剥离现有 special_effects |
| 怪物掉落装备 | 击杀怪物概率掉落带词缀装备 | 新增获取途径 |
| 洗炼系统 | 消耗洗炼石重随机词缀数值 | 新增 |
| 分解系统 | 销毁装备获得洗炼石 | 新增 |
| 锻造增强 | 锻造产出改为带随机词缀 | 改造现有锻造 |

### 2.2 数据流

```
锻造(材料+金币) ──┐
                  ├──> 装备实例(基础属性 + 随机词缀) ──> 穿戴 ──> 战斗
怪物掉落 ─────────┘         │                              │
                           │                              ├── 词缀: 战斗属性加成
                           │                              ├── 铭文: 触发效果(孔位)
                           │                              └── 宝石: 数值加成(孔位)
                           │
                           ├── 洗炼(洗炼石) ──> 重随机词缀数值
                           └── 分解 ──> 洗炼石 + 概率铭文提取
```

## 3. 装备词缀系统

### 3.1 词缀生成规则

通过锻造或怪物掉落获得的装备，自带随机词缀：

- 词缀数量由装备稀有度决定
- 每条词缀的数值在区间内随机浮动（产出时确定）
- 词缀绑定在装备上，不可拆卸
- 可通过"洗炼"重随机数值（类型不变）
- 存量老装备不受影响（无词缀，视为"素装"）
- 同一件装备上不会出现重复的词缀类型

**词缀数量：**

| 装备稀有度 | 词缀数量 | 规则 |
|-----------|---------|------|
| 白色 | 0~1条 | 50%概率带1条 |
| 绿色 | 1~2条 | 50%概率2条 |
| 蓝色 | 2~3条 | 50%概率3条 |
| 紫色 | 3~4条 | 50%概率4条 |
| 橙色 | 4条 | 必定满词缀 |
| 红色(VIP) | 不参与 | VIP装备豁免词缀系统 |

### 3.2 词缀分级

**T1 数值型词缀（约18种）：**

所有稀有度装备均可出现。提供战斗属性的固定百分比加成，数值在区间内随机浮动。

覆盖属性类型：暴击率、连击率、闪避率、反击率、穿透率、抗暴率、吸血率、命中率、暴击伤害、灵爆率、定身率、回复率、韧性(控制减免)、理智消耗减免、技能暴击率、无视防御(固定值)、格挡减伤、先手率。

每种词缀按装备稀有度有不同的数值区间，稀有度越高区间越大、上限越高。

**T2 触发型词缀（约20种）：**

仅蓝色及以上装备可出现。提供概率触发的战斗效果。

覆盖效果类型：恐惧、防御穿刺、暴击吸血、伤害反弹、坚韧减伤、真伤附加、先手打击、低血量斩杀加伤、护盾凝聚、击杀后加伤、闪避后必暴、绝境暴击、灵魂灼烧(理智)、周期回复、致残(降攻)、弱化(降防)、净化(移除debuff)、反制(被暴击眩晕)、连击叠伤、末日审判(斩杀)。

每种触发型词缀包含触发条件、触发概率区间、效果数值区间。

**T3 稀有型词缀（约4种）— Phase 2 实现：**

仅橙色装备可出现，每件装备最多1条。提供改变玩法的独特机制。

示例方向：致死保留、额外回合、失败补偿累积、保底伤害机制等。

> **注意：** T3 词缀需要深度修改 EnhancedBattleEngine 的核心战斗循环（死亡判定、回合控制等），实现复杂度远高于 T1/T2。建议在 Phase 2 实现，Phase 1 先上线 T1 + T2。

### 3.3 词缀与升阶关系

- 升阶只影响装备基础属性（attr_bonus 和 attr_ratio 乘以升阶倍率）
- 词缀完全不受升阶影响，升阶不会改变、丢失或增加词缀
- 升阶消耗副装备时，副装备的词缀直接消失（无法继承）

### 3.4 数据存储

词缀数据存储在 ItemInstance 的 `extra_attrs` JSON 字段中，新增 `_affixes` 键：

```python
extra_attrs = {
    "_persist_bonus": {...},  # 现有：装备属性持久化缓存
    "_affixes": [             # 新增：词缀列表
        {
            "affix_id": "critical_rate",   # 词缀类型ID
            "tier": "T1",                  # T1/T2/T3
            "value": 4.5,                  # 随机数值（T1为单值）
            "value2": null,                # T2可能有第二数值（如概率+效果值）
        },
        {
            "affix_id": "fear_strike",
            "tier": "T2",
            "value": 12,                   # 触发概率12%
            "value2": 1,                   # 持续1回合
        }
    ]
}
```

## 4. 铭文系统

### 4.1 核心概念

将现有非VIP装备的 `special_effects` 剥离为独立的"铭文"物品。铭文可插入装备孔位，与宝石共用（每孔二选一）。

**铭文 vs 词缀的区别：**

| | 词缀 | 铭文 |
|--|------|------|
| 存在形式 | 绑定在装备上 | 独立物品 |
| 可否拆卸 | 不可拆，只能洗炼数值 | 可装可拆 |
| 获取方式 | 装备产出时随机生成 | 怪物掉落、分解提取 |
| 占用位置 | 不占孔位 | 占用宝石孔位 |
| 描述风格 | — | 纯机制描述，无装备风味文案 |

### 4.2 铭文物品设计

铭文作为新的物品类型加入 items.yaml，type 为 `INSCRIPTION`。

```yaml
- item_id: "inscription_fear"
  name: "铭文：恐惧之力"
  description: "攻击时X%概率使敌人恐惧1回合"
  type: "INSCRIPTION"
  rarity: "blue"
  price: 15000
  inscription_effect:
    trigger: "on_attack"
    effect: "fear"
    duration: 1
    chance_ranges: [5, 15]  # 数值浮动区间
```

铭文和宝石一样有品质浮动 — 同种铭文掉落时效果数值随机。

**铭文随机数值存储：** 铭文的 ItemInstance.extra_attrs 中存储该实例的随机数值：

```python
# 铭文 ItemInstance 的 extra_attrs
{"_inscription_values": {"chance": 12}}  # 该铭文实例的触发概率为12%
```

### 4.3 铭文来源

- **怪物掉落** — 主要来源，精英怪和Boss概率掉落
- **分解提取** — 分解带T2词缀的装备时，有概率将该词缀提取为对应铭文
- **后期扩展** — 可开放铭文锻造（材料合成）

### 4.4 铭文孔位存储方案

**核心问题：** 现有 `gem_slots_data` 存储格式为 `{slot_index: gem_item_id}`（模板ID字符串）。宝石没有随机数值所以只需模板ID。但铭文有品质浮动，存储模板ID会丢失随机数值。

**解决方案：** 扩展 `gem_slots_data` 的值格式，铭文孔位存储完整数据：

```python
gem_slots_data = {
    "0": "critical_bead_1",                    # 宝石：仍然只存模板ID（向后兼容）
    "1": {                                      # 铭文：存储字典，包含模板ID+随机数值
        "item_id": "inscription_fear",
        "values": {"chance": 12}                # 该铭文实例的随机数值
    }
}
```

**判断孔位类型：** 值为字符串则为宝石（向后兼容），值为字典则为铭文。

**镶嵌铭文时：** 读取铭文 ItemInstance 的 `_inscription_values`，连同 item_id 一起写入孔位。然后消耗铭文 ItemInstance。

**拆卸铭文时：** 从孔位数据中恢复完整铭文信息，创建新的铭文 ItemInstance 并写入 `_inscription_values`，归还到背包。

### 4.5 铭文装卸

复用现有宝石镶嵌/拆卸机制，GemSocketService 需以下改造：

- `is_socketable_item()` — 扩展支持 `INSCRIPTION` 类型（当前硬编码只认 `GEM`）
- `get_gem_type()` — 增加铭文类型识别分支
- `socket_gem()` — 铭文镶嵌时写入字典格式而非字符串
- `remove_gem()` — 铭文拆卸时从字典恢复完整铭文实例

具体规则：
- **镶嵌** — 消耗镶嵌锤x1 + 金币（复用现有宝石镶嵌的工具和费用）
- **拆卸** — 消耗拆卸凿x1 + 金币，15%损坏风险（复用现有规则）
- **稳定水晶** — 保护拆卸100%安全（复用现有规则）
- **升阶回收** — 升阶消耗副装备时，铭文和宝石一样自动回收到背包。回收时从孔位字典恢复铭文实例。背包满时按铭文 price 折算为金币（与现有宝石回收策略一致）。

### 4.6 现有 special_effects 迁移

**影响范围：** 当前非VIP装备中只有少量装备有 special_effects（如镇魂幡的恐惧效果）。

**迁移方案（分阶段）：**

1. **Phase 1 — 新旧并存：** 先上线铭文系统，现有装备的 special_effects 暂时保留不动。新掉落/锻造的装备走词缀系统，铭文从掉落和分解获得。玩家自然过渡。

2. **Phase 2 — 正式迁移：** 上线一段时间稳定后，执行一次性迁移：
   - 移除非VIP装备 items.yaml 中的 `special_effects`
   - 对应效果转化为铭文物品定义
   - **补偿脚本：** 遍历所有玩家已持有的带 special_effects 装备，为每件装备的每个效果发放对应铭文物品到玩家背包（背包满则折算金币）
   - 代码中 `battle_effect_register.py` 的 `create_bridges_from_equipment_config()` 保留对 `special_effects` 的读取逻辑，但非VIP装备不再有此配置

3. **迁移涉及代码文件：** `battle_effect_register.py`、`enhanced_engine.py`、`integration_helper.py`、`equipment_commands.py` 等约12个文件引用了 `special_effects`，需逐一检查适配。

VIP装备（斩龙闪、归雨、镜怨披风等）的 special_effects 始终保持不变。

## 5. 怪物掉落装备

### 5.1 掉落规则

击杀怪物时，有概率掉落装备。掉落的装备自带随机词缀。

| 怪物类型 | 装备掉落率 | 可掉稀有度 |
|---------|-----------|-----------|
| 普通怪 | 1~3% | 白/绿 |
| 精英怪(诡域深层) | 5~10% | 绿/蓝 |
| Boss(世界Boss等) | 30~50% | 蓝/紫 |

### 5.2 掉落装备匹配

按怪物等级匹配掉落装备的等级段：

| 怪物等级 | 掉落装备等级段 | 对应稀有度 |
|---------|-------------|-----------|
| 1-20 | 初级装备 | 白色 |
| 21-60 | 中级装备 | 绿色 |
| 61-100 | 高级装备 | 蓝色 |
| 101+ | 顶级装备 | 紫色 |

### 5.3 铭文掉落

精英怪和Boss除了装备外，还有概率掉落铭文物品：

| 怪物类型 | 铭文掉落率 | 铭文品质 |
|---------|-----------|---------|
| 精英怪 | 3~5% | 绿/蓝 |
| Boss | 15~30% | 蓝/紫 |

**背包溢出处理：** 装备掉落不受背包容量限制（现有规则：装备不占背包格）。铭文为 `INSCRIPTION` 类型，也不占用背包格（与装备相同处理），避免因背包满而丢失掉落。

### 5.4 Boss专属装备（预留）

高等级Boss专属装备预留给未来里界玩法，当前版本不实现。设计时预留扩展接口即可。

## 6. 洗炼系统

### 6.1 功能

对装备自带词缀的数值进行重随机。

### 6.2 规则

- 消耗"洗炼石"x1
- 选择装备上的一条词缀
- 该词缀类型不变，数值在原区间内重新随机
- 例如：暴击率从3.2%重随机，可能变成5.1%也可能变成2.8%
- 不能对无词缀的素装使用

**交互流程（预览确认制）：**

1. 玩家输入 `【洗炼 装备编号 词缀序号】`
2. 系统显示当前词缀数值、所属区间、消耗材料
3. 玩家回复 `【确认洗炼】` 执行，数值直接覆盖（不支持保留旧值）
4. 展示洗炼结果，标注数值变化方向（上升/下降）

> 不采用"预览新值后选择是否接受"的锁定机制，保持赌博感。但展示区间让玩家做知情决策。

### 6.3 洗炼石来源

- 怪物掉落（低概率）
- 分解装备获得（主要来源）

### 6.4 指令

`【洗炼 装备编号/名称 词缀序号】`

## 7. 分解系统

### 7.1 功能

销毁装备获得洗炼石，带T2词缀的装备有概率额外提取铭文。

### 7.2 产出

| 装备稀有度 | 基础洗炼石 | 有词缀时额外洗炼石 |
|-----------|-----------|------------------|
| 白色 | 1个 | 有词缀+1个，无词缀+0 |
| 绿色 | 2个 | 有词缀+1~2个，无词缀+0 |
| 蓝色 | 4个 | 有词缀+2~3个，无词缀+0 |
| 紫色 | 8个 | 有词缀+3~4个，无词缀+0 |
| 橙色 | 15个 | 有词缀+4~5个，无词缀+0 |

> 无词缀的素装（老装备）也可分解，只获得基础洗炼石。

**铭文提取：** 分解带T2触发型词缀的装备时，每条T2词缀有30%概率提取为对应铭文物品。

### 7.3 限制

- 分解不可逆
- 已装备的物品需先卸下才能分解
- VIP装备不可分解
- 正在市场挂牌（`_frozen_for_trade`）或拍卖中（`_frozen_for_auction`）的装备不可分解

### 7.4 指令

`【分解 装备编号/名称】`

## 8. 锻造增强

### 8.1 改造内容

现有锻造流程不变（材料+金币在工坊附近锻造），但产出改为带随机词缀：

- 锻造结果消息增加词缀展示
- 同一配方每次锻造可能产出不同词缀组合
- 玩家有动力反复锻造追求极品词缀

### 8.2 现有装备 special_effects 处理

- 移除所有非VIP装备 items.yaml 中的 `special_effects` 配置
- 对应效果转化为铭文物品加入铭文掉落表
- VIP装备保持不变

## 9. 指令汇总

### 9.1 新增指令

| 指令 | 说明 |
|------|------|
| `【洗炼 装备编号/名称 词缀序号】` | 消耗洗炼石，重随机指定词缀数值 |
| `【分解 装备编号/名称】` | 分解装备获得洗炼石（+概率铭文） |
| `【铭文列表】` | 查看背包中的铭文物品 |

### 9.2 改造指令

| 指令 | 改造内容 |
|------|---------|
| `【装备详情 编号/名称】` | 增加词缀展示区域 |
| `【锻造 装备名】` | 产出带随机词缀，结果消息增加词缀展示 |
| `【镶嵌 编号 孔位 物品名】` | 支持镶嵌铭文（与宝石共用入口） |
| `【拆卸 编号 孔位】` | 支持拆卸铭文（与宝石共用入口） |

```
  [1] 锐利：暴击率+3.2%
  [2] 防御穿刺：攻击时12%概率无视敌人22%防御(2回合)

```

## 10. 战斗引擎集成

### 10.1 词缀生效

**T1 数值型词缀：** 在 BattleAttributeCalculator 计算战斗属性时，读取装备的 `_affixes` 数据，将T1词缀值累加到对应战斗属性上。

**T2 触发型词缀：** 复用现有 BattleEffectManager 的触发检查机制。在战斗初始化阶段，将装备的T2词缀注册为 BattleEffect，参与正常的触发-效果流程。

**T3 稀有型词缀：** 需要在 EnhancedBattleEngine 中增加专门的处理逻辑（如致死保留、额外回合等）。

### 10.2 铭文生效

铭文插入孔位后，其效果和宝石属性一样在装备穿戴时生效。铭文的触发效果同样注册到 BattleEffectManager 中。

### 10.3 效果优先级

多个同类效果（如多个吸血来源）按现有叠加规则处理 — 相同类型+不同来源可以共存。

## 11. 技术实现要点

### 11.1 数据模型变更

- `ItemInstance.extra_attrs` 增加 `_affixes` 键存储词缀数据（以 `_` 前缀开头，不会被 `apply_attr_bonus` 误读为属性值）
- `ItemInstance.extra_attrs` 铭文实例增加 `_inscription_values` 键存储随机数值
- `ItemInstance.gem_slots_data` 值格式扩展：字符串=宝石(向后兼容)，字典=铭文
- `ItemType` 枚举新增 `INSCRIPTION` 类型（存储为字符串，无需数据库ENUM迁移）
- items.yaml 新增铭文物品定义
- items.yaml 的 special_effects 迁移按 4.6 节分阶段执行
- 新增洗炼石等消耗品定义
- `INSCRIPTION` 类型物品不占用背包格（与 `EQUIPMENT` 相同处理，需在 `add_item` 中增加判断）

**重要约束：** 词缀数据只通过 `_affixes` 键存储和读取。禁止在 `extra_attrs` 顶层直接放置战斗属性键值（如 `critical_rate: 5`），避免与 `apply_attr_bonus` 的属性遍历产生双重加成。

### 11.2 新增服务

- `AffixService` — 词缀生成、洗炼逻辑
- `DecomposeService` — 装备分解逻辑
- `AffixConfig` — 词缀池配置（建议独立 YAML 文件 `affixes.yaml`）

### 11.3 改造服务

- `ForgeService`（锻造）— 产出时调用 AffixService 生成随机词缀
- `BattleAttributeCalculator` — 读取词缀加成战斗属性
- `BattleEffectManager` — 注册词缀和铭文的触发效果
- `EquipmentService` — 装备详情展示增加词缀区域
- `GemSocketService` — 扩展支持铭文镶嵌（复用孔位逻辑）

### 11.4 配置文件

新增 `plugins/xiuxian_game/data/affixes.yaml`，定义完整词缀池：

```yaml
affixes:
  t1:
    - affix_id: "critical_rate"
      name: "锐利"
      attribute: "critical_rate"
      ranges:
        white: [1, 2]
        green: [2, 4]
        blue: [3, 6]
        purple: [5, 8]
        orange: [7, 10]
    # ... 更多T1词缀（约18种）

  t2:
    - affix_id: "fear_strike"
      name: "恐惧之力"
      trigger: "on_attack"
      effect: "fear"
      chance_ranges:           # 触发概率区间（value）
        blue: [5, 8]
        purple: [8, 12]
        orange: [12, 15]
      duration_ranges:         # 持续回合区间（value2），若所有稀有度相同可简写为固定值
        blue: [1, 1]
        purple: [1, 1]
        orange: [1, 2]
    - affix_id: "defense_pierce"
      name: "防御穿刺"
      trigger: "on_attack"
      effect: "defense_penetration"
      chance_ranges:           # 触发概率
        blue: [10, 15]
        purple: [15, 20]
        orange: [20, 25]
      value_ranges:            # 穿透百分比（value2）
        blue: [15, 20]
        purple: [20, 25]
        orange: [25, 30]
      duration_ranges:
        blue: [2, 2]
        purple: [2, 2]
        orange: [2, 3]
    # ... 更多T2词缀（约20种）

  t3:
    - affix_id: "undying"
      name: "不灭"
      description: "每场战斗首次致死伤害时保留1HP"
      rarity_required: "orange"
    # ... 更多T3词缀（约4种，Phase 2实现）
```

> T2 词缀配置中，`chance_ranges` 对应数据结构中的 `value`（触发概率），`value_ranges`/`duration_ranges` 对应 `value2` 或独立字段。具体映射关系由 AffixService 在生成时处理。

## 12. 实施阶段

| 阶段 | 内容 | 说明 |
|------|------|------|
| Phase 1 | 词缀系统(T1+T2) + 锻造增强 + 装备详情展示 | 核心功能，让装备有个体差异 |
| Phase 2 | 铭文系统 + 分解系统 + 洗炼系统 | 效果自由搭配 + 词缀优化 |
| Phase 3 | 怪物掉落装备 + 怪物掉落铭文 | 新获取途径 |
| Phase 4 | special_effects 迁移（含补偿脚本） | 旧效果转铭文 |
| Phase 5 | T3 稀有词缀 | 高复杂度战斗机制词缀 |

每个阶段可独立上线、独立测试，降低单次变更风险。
